## 产品走查

### Outlook

Outlook 当前页面具有明确的多层信息架构：48px 顶栏、40px 应用轨、约 188px 文件夹树、351px 邮件列表、阅读窗格和 40px 命令栏。命令按钮约 32px 高；邮件行约 82px。它通过 Fluent 中性色、4px 圆角、列表阴影、分区留白和稳定的选中/悬停状态建立层级。

### 番茄

番茄正文由带动态字体 class 的 `.muye-reader-box` 承载。原生工具条是约 56px 宽的竖向浮动控件，包含加书架、目录、夜间、字号等项目。目录由真实用户点击后在页面 DOM 中生成 `.reader-catalog .chapter[data-item-id]`；完整数量以实际 DOM 为准，参考页曾取得 1087 个唯一章节 ID。

### 当前扩展

当前外壳为 56px 顶栏、44px 工具栏和 `220px / 310px / 剩余宽度` 三栏。左栏只有静态“收件箱·章节/已读章节”，没有筛选行为；没有 Outlook 应用轨、功能化搜索或邮件列表密度。

目录控件样式实测为 54×32、10px 字号、8px 圆角和灰底；上一封/下一封约 66×37、14px 字号、4px 圆角和透明底。用户指出的 UI 不一致成立，原因是番茄原生样式仍压过扩展样式。

## 代码架构 Review

### 保留的正确决策

- Manifest 只声明 `storage`，精确匹配阅读页。
- 正文使用同一原生节点，不复制正文或动态字体。
- 适配器、存储、搬运和皮肤已有基础边界。
- 恢复失败使用停用状态加当前页面刷新兜底。
- 自动测试覆盖身份、导航、恢复、目录状态和静态权限。

## PRD/spec Critique

审计前仓库没有正式 PRD，导致“Outlook 风格”的保真程度、左栏语义、搜索边界和退出指标没有产品层决策。

旧 spec 存在以下矛盾：

- 把 `/reader/<id>` 当作 `bookId`，但真实路径数字是章节 ID。
- 描述合成点击原生目录，和当前可信用户事件路线冲突。
- 实施计划要求搜索行，后续测试又要求删除无功能搜索框。
- 以“193 条级别目录”验收，和完整阅读页目录不符；数量必须以实际 DOM 为准。
- 模块图没有反映目录 bridge、目录控制器与当前恢复逻辑。

M0 已通过正式 PRD 和目标技术 spec 统一这些决策。

## M3.0 更新

reader 页原生目录停靠、透明命中层、synthetic click 与默认隐藏 iframe 路线不再作为运行时方案。M3.0 改为：点击“同步邮件”后提示用户真实点击番茄原生“目录”，观察阅读页实际目录节点，目录关闭后再原子渲染；失败后仅由用户明确点击“打开作品页同步”进入一次性页面回退。该路径仍需 Chrome/Edge 实机确认，自动测试不等于真实页面通过。

## 当前里程碑结论

产品目标、用户任务、信息架构、功能边界、身份模型、目录同步路线、成功指标、风险与验收矩阵已经形成单一基线。M3.0 原生阅读页同步已完成本地实现与自动验证，M3.1 搜索/筛选和 M4 兼容矩阵仍需独立验收；真实 Chrome/Edge 仍需按矩阵验收，本报告不把自动测试当作实机通过。
